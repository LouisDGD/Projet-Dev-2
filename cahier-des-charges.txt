1. Contexte

1.1 Présentation du client : 

Jacqueline Moreau, ancienne professeure de physique, coordinatrice bénévole du Repair Café "La clé a Molette" a Forest, crée il y a 4 ans avec des voisins.
Les membres se retrouvent une fois par mois, le deuxième samedi du mois de 14h à 17h, à la maison de quartier de Forest. Les gens viennent avec des objets a réparer et les bénévoles les aident a réparer gratuitement. Ils ne réparent pas a leur place mais aident a réparer.

1.2 Présentation du projet :

Actuellement, chaque objet a sa propre fiche papier a l'accueil mais ces fiches passent de main en main et se perdent, personne ne sait qui travaille sur quoi ni quand. Après la session, le petit fils de Mme Moraud, recopie tout ces papiers dans un excel pour un rapport a la commune, mais il part en érasmus en février, ils auraient besoin d'un outil simple pour remplacer ces fiches et l’Excel, sur le vieil ordinateur portable de l’association.

1.3 Objectifs du projet :
- Retrouver facilement une fiche quand quelqu'un revient avec son objet 
- Faire plus facilement les rapports a la commune

2. Description générale

2.1 Vue d'ensemble du produit et de son environnement

 - Une application/Site (en local) utilisée depuis l'unique ordinateur Windows du Repair Café
 - Celle-ci doit avoir un historique des objets réparer, être capable d'enregistrer un nouvel objet (en attente de réparation), un des bénévoles doit pouvoir facilement prendre en charge un dossier et les autres doivent le voir (synchroniser)
 - Il faut pouvoir faire un rapport avec les informations nécéssaire a la commune (revoir avec Mme Moreau)
 - L'ordinateur n'ayant pas un accès a internet stable, il faut que les fonctionnalitées soient éxclusivement hors-ligne.

2.2 Profils utilisateurs (acteurs)

 - Il éxiste plusieurs utilisateurs ayant le même profil; des bénévoles du quartier avec des niveaux en informatique variable, qui encodent les données des différents dossiers dont ils s'occupent.

2.3 Périmètre

Inclus: 
 - Un historique complet ainsi qu'un système de recherche facile a utiliser.
 - La possibilité d'enregistrer de nouvelle données (un objet a réparer)
 - Une fonction pour imprimer directement un dossier ou un groupe de dossiers (gràce a la recherche)
 - Avoir un feedback en temps réel de l'état d'un dossier.

Exclus: 
 - Un accès a internet.

2.4 Règles métier

 - RM-01: L'application est en Python
 - RM-02: L'application est accessible pour différent niveaux d'aisance informatique.
 - RM-03: Un historique, de la recherche, de la création le tout synchronisé.

2.5 Données
 - D-01 Application:
     - Contenu: Un éxécutable, les fonctionnalités de l'application.
     - Volume: Autant que le PC de la cliente le permet.
     - Origine: 
     - Conservation: "Infifnie", tant que Mme Moreau utlisera l'ordinateur.
 - D-02 Gestion des dossier:
     - Contenu: Un historique des dossiers, la création de dossiers, la recherche de dossiers
     - Volume: Autant que nécéssaire
     - Origine: Client amenant leurs objets a réparer
     - Conservation: lié a D-01
 - D-03 Exportation des dossiers pour la commune:
     - Contenu: Un dossier(s), les données liée a celui-ci dans un format adapté a la commune.
     - Volume: La fréquence a laquel un rapport est du pour la commune (à détermiener avec la cliente)
     - Origine: Les dossiers complet dans la base de données de l'application.
     - Conservation: Lié a D-01
3. Exigences

3.1 Exigences fonctionnelles

F-01 - Enregistrer les informations d'un objet a l'accueil : 

Auteur : Louis Degand
Acteur : Bénévoles de l'accueil
Description : Permettre aux bénévoles d'enregistrer les informations relatives a un objet pour en créer une fiche

 Exigences :

 - EF-01.1 : Le bénévole introduit le nom du visiteur, la marque, l'adresse mail ainsi que la description de l'objet 
 - EF-01.2 : Le type d'objet est choisi dans une liste, sans saisie libre
 - EF-01.3 : La fiche est automatiquement ajoutée a la file d'attente, par ordre d'arrivée (premier arrivé, premier servi)
 
 Critères d'acceptation : 
 
 - EF-01.1 : Un bénévole crée une fiche complète sans aide
 - EF-01.2 : Tout les types cités par le / la client(e) sont proposés dans la liste
 - EF-01.3 : La fiche apparaît en fin de file d'attente 
 
------------------------------------------------------------------------------------------

F-02 - Consultation des données pour les réparateur :

Auteur : Louis Degand
Acteur : Réparateurs du café, coordinatrice
Description : L'écran principal affiche la liste des objets de la session en cours et indique qui travaille sur quoi

 Exigences :
 
 - EF-02.1 : L'écran affiche pour chaque objet, le nom du visiteur, le type d'objet, le réparateur assigné et l'état (en attente, en cours, terminé)
 - EF-02.2 : Un réparateur peut prendre en charge un objet en y inscrivant son nom
 - EF-02.3 : L'application n'assigne jamais un objet automatiquement
 
 Critères d'acceptation : 
 
 - EF-02.1 : La coordinatrice peut consulter qui travaille sur quoi
 - EF-02.2 : Le réparateur a son nom inscrit sur la ligne de l'objet
 - EF-02.3 : Aucun objet n'a de réparateur automatiquement assigné

------------------------------------------------------------------------------------------

F-03 - Completer une fiche (diagnostic et résultat) :

Auteur : Louis Degand
Acteur : Réparateurs
Description : Le réparateur note son diagnostic et le résultat de la réparation

 Exigences :

 - EF-03.1 : Le réparateur saisit un diagnostic
 - EF-03.2 : Le réparateur saisit un statut pour la réparation (en cours, réparé, a suivre (Pièce manquante))
 
 Critères d'acceptation : 
 
 - EF-03.1 : Le diagnostic saisi par le réparateur est affiché
 - EF-03.2 : Le statut de la réparation saisi par le réparateur est affiché
 - EF-03.2 : Les objets avec le statut "A suivre" sont retrouvables les sessions suivantes

------------------------------------------------------------------------------------------

F-04 - Rechercher une fiche : 

Auteur : Louis Degand
Acteur : Responsable et réparateurs
Description : Les réparateurs ainsi que la responsable peuvent rechercher une fiche liée a un objet sans difficulté

 Exigences :

  - EF-04.1 : La recherche se fait par nom de visiteur
  - EF-04.2 : Un filtre affiche uniquement les objets a suivre 

 Critères d'acceptation :

  - EF-04.1 : En tapant "Dubois", la fiche du grille-pain de madame Dubois s'affiche (test proposée par la cliente)
  - EF-04.2 : Uniquement les objets avec la notion a suivre s'affichent

------------------------------------------------------------------------------------------

F-05 - Afficher les indicateurs de la sessions : 

Auteur : Louis Degand
Acteur : Responsable
Description : La responsable suit la progression de la session en cours.

Exigences :

 - EF-05.1 : L'application affiche le nombre d'objets arrivés, réparés et repartis sans solution

Critères d'acceptation : 

 - EF-05.1 : Les données correspondent au contenu de la liste et se mettent a jour automatiquement

------------------------------------------------------------------------------------------

F-06 - Generer le rapport imprimable pour la commune : 

Auteur : Louis Degand
Acteur : Responsable
Description : Génération automatique des rapports a fournir a la commune

Exigences : 

 - EF-06.1 : L'application génére un document imprimable sur une periode donnée
 - EF-06.2 : Le rapport indique le nombre d'objets recus, réparés, ainsi qu'une estimation du nombre de kilos de déchets évités
 - EF-06.3 : La responsable peut relire les rapports avant impression

Critères d'acceptation :

 - EF-06.1 : Le document est correctement mis en page et correspond bien a la periode renseignée
 - EF-06.2 : Les nombres sont corrects et correspondent aux chiffres réels
 - EF-06.3 : Les rapports sont affichés avant impression

------------------------------------------------------------------------------------------

F-07 - Gerer les coordonnées des visiteurs 

Auteur : Louis Degand
Acteur : Responsable et bénévoles 
Description : Les coordonnées ne sont enregistrées qu'avec l'accord des visiteurs et supprimées automatiquement après un an

Exigences : 

 - EF-07.1 : Les champs de coordonnées sont bloqués tant que le client n'a pas donné son accord et que la case n'est pas cochée.
 - EF-07.2 : Le système efface automatiquement les données 365 jours après leur enregistrement

Critères d'acceptation :

 - EF-07.1 : Le champ de coordonnées se débloque lors de la validation de l'accord du client
 - EF-07.2 : Le système a correctement effacé les données après 365 jours (avec des dates simulées, les coordonnées disparaissent et les fiches restent)
